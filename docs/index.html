Quick-Start Installation

Deploy `pisugar-fx` hardware instrumentation with a single setup command or manually via git and pip.

Automated One-Line Terminal Setup 
# One-line terminal setup script
curl -sSL https://raw.githubusercontent.com/pisugar-fx/main/setup.sh | bash
Standard Manual Installation Block 
# Clone repository and set up dependencies
git clone https://github.com/pisugar-fx/pisugar-fx.git
cd pisugar-fx
pip install -r requirements.txt

# Run validation test suite before hardware boot
python3 tests/flight_test.py

# Launch the flight tracker application
python3 flight_tracker.py --debug

Configuration Reference & Hardware Specifications

Hardware Bill of Materials (BOM), environment configuration parameters, and GPIO/I2C pinout specifications.

Hardware Bill of Materials (BOM)

Component Category Hardware Model / Module Technical Specifications Role & Interface
Compute Unit Raspberry Pi Zero 2 W Quad-core ARM Cortex-A53 @ 1.0GHz, 512MB LPDDR2, 802.11b/g/n Wi-Fi, Bluetooth 4.2 Primary host CPU running flight_tracker.py & daemon services
Battery Management PiSugar 2 / PiSugar 3 Stack Custom IC telemetry, real-time clock (RTC), onboard power button, soft shutdown triggers I2C bus power telemetry (0x57/0x75), battery status & power cycle management
Display Hardware WhisPlay 1.69" LCD / E-Paper ST7789 controller, 240×280 hardware resolution, RGB565 color format, tactile user button SPI bus radar screen, dead-reckoning flight markers, status LED density indicator
Radio Receiver RTL-SDR USB Dongle + Antenna R820T2 tuner, 1090MHz ADS-B decoding via readsb or dump1090 Local SDR mode live aircraft telemetry decoding (writing to /run/readsb/aircraft.json)

Environment & Parameter Reference

Parameter Name Default Value Env Var / Config Key Description & Operational Usage
source "local" DATA_SOURCE Operational data source: "local" (RTL-SDR antenna) or "api" (airplanes.live fallback)
AIRPORT_ORIGIN "OKC" AIRPORT_ORIGIN Origin airport IATA code for default center coordinates and flight origin tracking
AIRPORT_DEST "DFW" AIRPORT_DEST Destination airport IATA code for flight routing and distance vector calculations
REFRESH_INTERVAL 5 REFRESH_INTERVAL_SECONDS Frequency in seconds to poll aircraft data source and re-render display buffer
display_duration_seconds 30 DISPLAY_DURATION_SECONDS Screen dwell time before auto-cycling to next location entry (API mode)
brightness 100 DISPLAY_BRIGHTNESS WhisPlay LCD backlight level percentage (0 to 100)
ghost_enabled true GHOST_ENABLED Enable dead-reckoning ghost markers for aircraft experiencing signal loss
web_server_enabled true WEB_SERVER_ENABLED Enable background Flask web mirror daemon (serves /snapshot.jpg & /map on port 5000)

I2C & Pinout Configuration

Bus / Protocol GPIO Header Pin Signal Identifier Hardware Interface & Target Subsystem
I2C Bus GPIO 2 (Pin 3) SDA PiSugar battery RTC & power IC data line (I2C address 0x57/0x75)
I2C Bus GPIO 3 (Pin 5) SCL PiSugar battery RTC & power IC clock line
SPI Bus GPIO 10 (Pin 19) SPI_MOSI WhisPlay ST7789 LCD master-out data line
SPI Bus GPIO 11 (Pin 23) SPI_SCLK WhisPlay ST7789 LCD serial clock line
PWM Control GPIO 18 (Pin 12) RGB_LED_PWM WhisPlay onboard RGB density indicator LED (Blue/Green/Yellow/Orange/Red)
GPIO Input GPIO 24 (Pin 18) TACTILE_BTN WhisPlay tactile button (single-press location switch / refresh trigger)

System Features

Real-Time ADS-B Radar

Reads local SDR decoded frames directly from /run/readsb/aircraft.json every 1 second without internet dependencies.

Local SDR Mode

Dead-Reckoning Ghosts

Projects ghost trajectory vectors and fading trails for tracked aircraft during temporary antenna signal loss.

Track History

Flask Web Mirror & Map

Embedded Flask server running on port 5000 provides live JPEG snapshots and Leaflet.js interactive dark maps over Wi-Fi.

Port 5000

WhisPlay RGB LED Indicator

Onboard RGB status LED signals sky density at a glance: Blue (0 aircraft), Green (1-5), Yellow (6-15), Orange (16-30), Red (>30).
